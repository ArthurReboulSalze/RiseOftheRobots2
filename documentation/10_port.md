# 10 — C++ port status and next steps

The port is a native C++/SDL2 application using assets generated by the import pipeline. It needs a user-supplied original game copy; no game data belongs in Git.

## Build and layout

The verified Windows toolchain is Visual Studio 2022 / MSVC 14.44, CMake, SDL2 2.30.11, SDL2_image 2.8.4, SDL2_mixer 2.8.0, and nlohmann/json 3.11.3. `TOOLS/bootstrap_port.py` downloads official pinned dependency archives and checks their SHA-256. See the root README for the current commands. `PORT/CMakeLists.txt` builds the executable and copies required DLLs. `--assets` selects an imported asset profile.

The main source modules are `main.cpp`, `frontend.*` for menu and movie flow, `ui.*` for rendering, `settings.*` for saved options, `filters.*` and `presentation.*` for display filtering, `assets.*` for manifests and images, `announcer.*` for original speech, `fighter.*` for fighter state/commands, and `combat.*` for hits, original FX and round completion. `PORT/tests` contains synthetic checks and private-profile rendering checks.

## Current playable slice

The frontend shows the decoded `LLOGO` images, the `MAINSCR` title image, and `VSFACE` portraits. It lists 28 robots for the original copy or 30 for Director's Cut Disc 1. The two extra Director's Cut robots are `RBT2` (SHEEPMAN) and `RBT3` (BUNNYRABBIT). Their own palettes work, although matching `RB42/RB43` and `AG2/AG3` assets are absent. Selection loads each fighter's RBT atlas, MVS movement bank, and CL2 collision data.

The title's **OPTIONS** menu contains separate music/game volumes, easy finishings, six display modes and key mapping. Values persist in the selected profile's `ui/port_options.json`; attack bindings remain in `ui/rise2.cfg`. Easy finishings use available source actions after KO, with no repeated trigger from a held attack. Robot names and portraits now follow the native ABC…Z01 order, fixing the previous two-position name rotation. See [document 16](16_options_filters_and_fx.md) for controls, filter attribution and FX corrections.

The window defaults to 1280×800 with a 640×400 logical surface. The original high-resolution RBT sprites are the primary mode; extracted RB4 low-resolution assets exist but the optional VGA mode is not wired up. Rendering uses vertical sync. The simulation currently advances at approximately 15 Hz, based on user visual testing of the too-fast initial loop; exact DOS pacing and per-animation timing still need to be measured. The first prototype ran at about 60 Hz and caused repeated, vibrating directional animations. That bug was fixed; the user confirmed the result works, while button mapping remains provisional.

An MVS image index `i` selects `atlas.frames[i+1]` because an RBT atlas begins with an empty entry. The corresponding collision frame is `CL2.records[i]`. Sequence-end markers are never rendered. Sprite placement uses the stored canvas origin, and the second fighter mirrors correctly. The fighter loop handles idle and directional transitions, provisional attack actions, CL2 box checks, 120-HP health, a 24-point super meter, and hit flash. A successful fighter regression test does not replace comparison with the DOS game.

Physical inputs use screen directions, converted to facing-relative MVS masks: forward/back are `0x02/0x04`, punches/kicks `0x01/0x20`, up/down `0x08/0x10`. Walking uses movements 2/3 and standing attacks 8/9. The attack group must be released before another attack, as in the DOS builder. Up launches one jump per press. MVS control bytes determine completion; STS metadata supplies gravity and state flags. Jumps now rise and fall with the verified DOS fixed-point arithmetic, and collision boxes follow the vertical offset. Facing updates once before motion, respects the DOS state restrictions, and exchanges diagonal jumps 34/35 without restarting their trajectory. Ground turns use movements 68/69; attacks keep their orientation until completion. [Document 14](14_combat_inputs_and_jumps.md) details the source evidence, supported-bank restrictions and regression checks; [document 15](15_combat_commands_and_fx.md) covers the implemented strengths and commands. Exact DOS timing remains open. Collision coordinates scale x by four and y by two; the ground anchor is y=312 and the standing center reference near x=294. Shared projectile placement and boxes now use the owner's canvas projection, correcting shots that appeared near the floor.

## Video and menu limitations

The older supplied copy has only three ANI files; Director's Cut Disc 1 has 105. All supplied ANI layouts now convert with native playable frame limits and default timing from the 25 Hz movie counter. Optional original FLC sources also convert through locally installed FFmpeg. PLAYER browses the profile's movies, supports pause/seek and resolution/category selection, and queues the shared epilogue after a robot ending. Long clips stream one texture at a time. The inspected complete-media catalogue has 175 entries, including resolution variants and original placeholder cards. Campaign progression, movie music/cues and ending text remain incomplete.

Victory speech now uses each robot's normal MRW sample 14; Cyborg's recording was confirmed by the user. Supplemental original WAVs add standalone names at selection. Their location in base DOS data remains unconfirmed. Cyborg's single-button finishing was corrected by calculating distance from its signed death collision rather than a universal 100-pixel gap. [Document 17](17_finishings_voices_and_player.md) records source evidence and limits, including the unresolved native range-table indexing.

Damage tests suggest ordinary hits around 6–10 HP, or 12–20 hits from 120 HP, but the exact formula and defensive-state adjustments are documented in page 08. The Director's Cut profile is the source for complete-content work; its additional ANI files are now decoded.

## Verification and scope

The Release build and all four CTest checks pass. Asset checks pass with the 28- and 30-robot profiles, including saved options, key mapping, all six display filters and first/middle/last-frame loading for all 175 local movies. Headless combat verifies the real Cyborg uppercut in both directions, corrected shared projectiles, command-driven and single-button finishings, and Cyborg victim state 59 for both players/facings and wall positions. All 30 MVS banks were regenerated after the four descriptor flag bytes and displacement boundaries were corrected; 8,640 sequences and the old 28 atlas/CL2 mappings were checked. The 1,199 empty ANR frames are valid and must remain empty. These automated checks do not establish final animation speed, feel, sound/music, or full DOS visual fidelity; direct comparison and user playtesting remain necessary.
